# 마일스톤

각 마일스톤은 **완료 기준**을 모두 만족해야 끝난다. 끝날 때마다 Claude가 핵심 코드를 설명하고, 사용자가 검토한 뒤 다음으로 넘어간다.

```
M0 준비 ─▶ M1 검증 ─▶ M2 앱 골격(Mock) ─▶ M3 로그인·서버 기초 ─▶ M4 항공편 데이터
                                                                      │
          ┌───────────────────────────────────────────────────────────┘
          ▼
       M5 제보 ─▶ M6 알림 ─▶ ★ 핵심 기능 완성 ─▶ M7 위젯 ─▶ M8 Live Activity ─▶ M9 출시 준비
```

★ 지점에서 핵심 기능(F-01~F-07, F-10, F-11)이 모두 동작한다. 위젯·Live Activity(F-08, F-09)는 첫 출시 범위지만, 일정이 길어지면 ★ 지점에서 출시 범위를 다시 논의할 수 있다.

---

## M0. 준비

| 작업 | 담당 |
|---|---|
| 새 폴더 생성, `git init`, 이 `docs/` 복사 | Claude |
| 새 `AGENTS.md`, `SECURITY.md`, `README.md`, `.gitignore` 작성 (현재 결정 기준) | Claude |
| GitHub 공개 저장소 생성, 첫 푸시 | 사용자 확인 후 Claude |
| Firebase 프로젝트 생성 ([준비 체크리스트](setup-checklist.md)) | 사용자 |
| 공공데이터포털 API 4종 활용 신청 | 사용자 |
| Apple Developer: App ID, App Group, 기능(Sign in with Apple, 푸시, App Attest) | 사용자 (Claude 안내) |

**완료 기준**
- 새 저장소가 GitHub에 있고 비밀 정보가 없다.
- Firebase 개발 프로젝트가 도쿄 지역으로 만들어져 있다.
- 공공 API 개발 키를 받았다. (키는 저장소가 아닌 로컬·Secret Manager에만)

---

## M1. 검증 (시제품)

본 구현 전에 불확실한 것을 작은 코드로 확인한다. 시제품 코드는 본 코드에 넣지 않는다.

| 검증 | 확인 내용 | 결과 반영 |
|---|---|---|
| 공공 API 응답 | 묶음 조회 가능 여부, 코드쉐어, 자정 경계, 한국공항공사 게이트, 실제 한도 | `04-technical/data-sync.md` |
| 앱 안 언어 전환 | 앱 재시작 없이 바뀌는지, 위젯·알림 문구 처리 | `04-technical/architecture.md` |
| 공항 기본 데이터 | 출처·라이선스, 시간대 데이터 | `04-technical/architecture.md` |

- 실제 API 응답은 저장소에 커밋하지 않는다. 필요한 사례는 **가상 데이터로 다시 만든다.**

**완료 기준**: 세 항목의 결과가 문서에 반영되고, 설계 변경이 필요하면 사용자와 결정했다.

---

## M2. 앱 골격 + Mock 빌드

서버 없이 **목데이터로 모든 화면 흐름**을 완성한다.

| 작업 |
|---|
| Xcode 프로젝트 (iOS 18, Debug/Mock/Release 구성, 위젯 타깃은 M7에서 추가) |
| Domain: 모델, D-Day·현지 시각·상태·정보 항목 상태 계산 + 단위 테스트 |
| Repository 프로토콜 + Mock 구현 (가상 항공편, `샘플 데이터` 표시) |
| 화면 S-01 ~ S-10 (Mock 기준) |
| String Catalog 한·일·영 |
| 화면 모드 설정 + 전환 애니메이션 |

**완료 기준**
- `DFlight-Mock`으로 화면 설계의 모든 흐름과 상태(빈 목록, 미정, 자동 정보 없음, 확인 실패, 결항, 코드쉐어)를 시뮬레이터에서 볼 수 있다.
- Mock 빌드는 외부 통신을 하지 않는다.
- Domain 단위 테스트 통과.

---

## M3. 로그인·서버 기초

| 작업 |
|---|
| Firebase 연결 (Debug 구성만), App Check (App Attest) |
| Sign in with Apple, Google 로그인 |
| 서버 프로젝트 (TypeScript), 공통 검증·에러·한도 처리 |
| `updateSettings`, `registerDevice`, `deleteAccount` |
| Firestore Security Rules + 에뮬레이터 테스트 |
| 예산 알림 설정 |
| 강제 업데이트(`config/app`), 공지사항(`notices`) 목록·중요 공지 팝업 |

**완료 기준**
- 실기기에서 두 방식으로 로그인·로그아웃·계정 삭제(Apple 토큰 해지 포함)가 된다.
- 다른 사용자의 데이터를 읽을 수 없다는 규칙 테스트가 통과한다.
- App Check 없는 호출이 거부된다.

## M4. 항공편 데이터

| 작업 |
|---|
| 공공 API 공급원 (`providers/`), 응답 정규화 + 가상 응답 기반 테스트 |
| `searchFlight`, `trackFlight`, `createManualFlight`, `untrackFlight` |
| `pollFlights` (조회 주기, 변경 감지, 호출 한도 보호), `dailyCleanup` |
| 앱 Live Repository: Firestore 구독, 오프라인 캐시 |
| S-03 ~ S-06 실제 데이터 연결 |

**완료 기준**
- 인천 출발·도착 실제 항공편을 등록하면 터미널·게이트가 표시되고 갱신된다.
- 한국 공항이 없는 항공편은 '못 찾음' → 직접 입력 등록이 된다.
- 변경 감지·조회 주기·한도 보호 테스트 통과.

## M5. 사용자 제보

| 작업 |
|---|
| `submitReport`, 제보 이력, 30일 정리 |
| S-07 제보 화면, 형식 입력 |

**완료 기준**
- 두 계정으로 같은 항공편을 등록하면 한쪽 제보가 다른 쪽에 `사용자 제보`로 보인다.
- 공항 데이터 항목은 수정이 거부된다. 등록하지 않은 사용자의 수정이 거부된다.

## M6. 알림

| 작업 |
|---|
| FCM 연결, 변경 알림 발송 (사용자 언어, 묶음 알림) |
| 로컬 임박 알림 예약 (최대 60개, 시각 변경 재예약) |
| S-02 알림 허용 안내, 설정의 알림 항목 |
| 알림 누르면 상세 화면으로 이동 |

**완료 기준**
- 실기기에서 변경 알림과 임박 알림 3종을 받는다.
- 출발 시각이 바뀌면 임박 알림이 바뀐 시각으로 다시 예약된다.

**★ 핵심 기능 완성**: 여기서 출시 범위를 한 번 점검한다.
