## 결정 사항 (2026-10-12)

| # | 결정 | 근거 |
|---|---|---|
| D-01 | 운영비 목표 **월 1,000엔 유지**. 유료 항공 데이터는 첫 출시에 쓰지 않는다. | 유일한 후보인 AeroDataBox Pro만으로 약 1,125엔 (R-1, R-5) |
| D-02 | 자동 항공 데이터는 **한국 공공 API**(인천공항, 한국공항공사)만 사용한다. 한국 공항 쪽 정보만 자동으로 받는다. | 무료이고 상업 이용 제한 없음 (R-1) |
| D-03 | 한국 공항 외 정보는 **사용자 제보**로 채운다. | D-02 |
| D-04 | 유료 데이터를 나중에 붙일 수 있도록 서버의 데이터 공급원을 교체 가능하게 설계한다. 추가 시점은 결정 대기. | 사용자 증가 대비 |
| D-05 | 서버가 외부 API를 **항공편 단위로 한 번만** 조회해 DB에 저장하고, 앱은 DB만 읽는다. 공공 API 하루 한도를 넘지 않도록 서버에 호출 상한을 둔다. | 호출량을 사용자 수가 아닌 항공편 수에 비례시킴 |
| D-06 | 사용자 제보는 **형식이 정해진 입력**만 받는다. 신고·차단 기능은 첫 출시에 넣지 않는다. | 사용자 결정. 심사 반려 위험은 아래 참고 |
| D-07 | **계정 삭제**를 첫 출시에 포함한다. Apple 로그인 토큰 해지 포함. | App Store 필수 (R-4) |
| D-08 | 최소 지원 버전 **iOS 18**. | Live Activity 서버 시작·일괄 갱신을 분기 없이 사용 (R-3) |
| D-09 | 첫 출시 공항 안내는 **공식 안내도 링크 + 지도 앱 링크**. 이미지는 복사하지 않는다. | Apple 실내 지도 사용 불가 (R-2) |
| D-10 | 시간 임박 알림은 **로컬 알림**으로 예약하고, 시각 변경은 서버 알림 후 앱에서 다시 예약한다. | 백그라운드 푸시는 전달 보장 없음 (R-3) |

## 알려진 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 사용자 제보에 신고·차단이 없음 | App Store 가이드라인 1.2로 **반려될 수 있다.** | 반려 시 신고·차단·연락처를 추가한다. |
| 일본 공항 자동 데이터 없음 | 하네다·나리타 등 일본 공항 쪽 터미널·게이트는 제보가 없으면 비어 있다. | 화면에 '자동 정보 미제공 공항' 안내. 유료 데이터 추가 검토 (D-04) |
| 한국공항공사 공항에 터미널 없음 | 김포·김해·제주 등 인천 외 한국 공항은 터미널 필드가 없다. 게이트는 당일 `flight-status/info`에 있다. | 터미널은 사용자 제보. 게이트는 당일 묶음 조회 (TD-15) |
| 인천공항 실시간 정보는 D-3부터 | 그 전에는 게이트 등이 비어 있다. D-3~D+6과 일정 API 존재 확인은 2026-10-12에 맞았다. | 정기 운항 시간표로 항공편 존재만 확인 |
| Live Activity 최대 8시간 | 장거리 항공편은 도착 전에 표시가 끝난다. | 시작 시점을 03-design에서 정한다. |
