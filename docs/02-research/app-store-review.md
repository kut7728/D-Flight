# R-4. App Store 심사 기준

| 항목 | 내용 |
|---|---|
| 조사일 | 2026-10-12 |
| 관련 기획 | F-01, F-07 |

## 1. 로그인 (가이드라인 4.8)

Google 로그인을 제공하면 아래 조건을 만족하는 다른 로그인 수단도 함께 제공해야 한다.
- 이름과 이메일만 수집
- 사용자가 이메일을 숨길 수 있음
- 동의 없이 광고용 정보를 수집하지 않음

**Sign in with Apple**이 이 조건을 만족하므로 기획대로 두 가지를 함께 제공하면 된다.

## 2. 계정 삭제 (가이드라인 5.1.1(v))

- 계정을 만들 수 있는 앱은 **앱 안에서 계정 삭제**를 제공해야 한다.
- 비활성화만으로는 안 되고 계정과 데이터를 지워야 한다. 전화나 이메일로 요청하게 하면 안 된다.
- Sign in with Apple 사용자는 삭제 시 **Apple 토큰도 해지**해야 한다.

> ⚠️ 기획서에 계정 삭제 기능이 없다. F-01에 추가가 필요하다.

## 3. 사용자 생성 콘텐츠 (가이드라인 1.2)

사용자가 올린 내용을 다른 사용자가 보는 앱은 아래 네 가지를 모두 갖춰야 한다.
1. 부적절한 내용 **필터링**
2. **신고** 기능과 신속한 대응
3. 악용 사용자 **차단**
4. 연락처 공개

**F-07(사용자 제보 공유)이 해당하는지**: Apple은 범위를 좁게 정의하지 않는다. 다른 사용자에게 보이는 입력이면 **해당한다고 보고 대비하는 것이 안전하다.** (해석이며 공식 확인은 아님)

대응 방법:
- 자유 텍스트 대신 **형식이 정해진 입력**(터미널 목록 선택, 게이트는 영문·숫자만)으로 받아 필터링을 단순하게 한다.
- '잘못된 정보 신고', 특정 제보자 정보 숨기기(차단), 지원 연락처를 제공한다.
- 또는 첫 출시에는 제보를 **본인에게만 보이게** 해서 이 조건을 피한다.

## 4. 개인정보

- **개인정보 매니페스트**(앱과 SDK가 쓰는 민감 API의 사용 이유 신고)가 필수다.
- App Store Connect의 **개인정보 라벨**에 로그인 식별자, 푸시 토큰, 저장한 항공편을 신고해야 한다.
- **개인정보 처리방침** 페이지가 필요하다. (07-release)
