## 1. 한 줄 소개

> 예매한 항공편을 등록해 두면 출발(D-Day)까지 일정을 지켜 주고, 터미널·게이트·체크인 위치를 알려 주는 iOS 앱.

앱 이름은 **D-Day + Flight**에서 왔다. 출발일까지 남은 날짜가 앱의 중심 개념이다.

## 2. 해결할 문제

| 문제 | 실제 경험 |
|---|---|
| 출발 시각을 잘못 알고 있음 | 항공권 시간을 잘못 알아 비행기를 놓친 적이 있다. |
| 터미널이 헷갈림 | 탈 때마다 몇 번 터미널인지 다시 찾아야 한다. |
| 게이트를 따로 찾아야 함 | 게이트는 늦게 정해지고 바뀌기도 해서 직접 계속 확인해야 한다. |
| 게이트 위치를 모름 | 게이트 번호를 알아도 공항 안 어디에 있는지 알기 어렵다. |
| 변경 사항을 늦게 앎 | 지연·게이트 변경을 놓치기 쉽다. |

## 3. 대상 사용자

- **해외 거주자**: 고국과 거주국을 자주 오가는 사람
- **출장이 잦은 직장인**
- **여행을 자주 가는 사람**

공통점은 **이미 항공권을 예매한 사람**이라는 것이다. 항공권을 고르고 있는 사람은 대상이 아니다.

## 4. 사용 흐름

| 시점 | 사용자 행동 | 앱이 하는 일 |
|---|---|---|
| 예매 직후 | 편명과 날짜를 입력해 등록 | 항공편 정보를 찾아 보여 주고 D-Day를 표시 |
| 출발 전 | 평소에는 앱을 열지 않음 | 정보가 바뀔 때마다 알림 |
| 출발 24시간 전 ~ 당일 | 알림을 받고 확인 | 시간 임박 알림, 위젯·Live Activity 표시 |
| 공항 가는 길 / 공항 안 | 터미널·게이트·체크인 위치 확인 | 최신 정보와 공항 안내도 링크 제공 |
| 도착 후 | 수하물 수취대 확인 | 도착 정보 표시 후 '지난 항공편'으로 이동 |

## 5. 첫 출시 기능 (MVP)

### F-01. 로그인
- 앱을 처음 열 때 로그인해야 한다.
- 로그인 수단은 **Sign in with Apple**과 **Google 로그인**이다.
- 이유: 서버가 사용자별 등록 항공편을 알아야 변경 알림을 보낼 수 있고, 공유 정보 수정자를 식별해야 한다. 기기를 바꿔도 항공편 목록이 유지된다.
- 앱 안에서 **계정을 삭제**할 수 있다. 계정과 데이터를 지우고, Apple 로그인 사용자는 Apple 토큰도 해지한다. (App Store 필수)

### F-02. 항공편 등록
- **편명 + 출발 날짜**를 입력해 등록한다. (예: `NH203`, `2026-11-01`)
- 항공 데이터에 항공편이 없으면 사용자가 직접 정보를 입력해 등록할 수 있다. (F-07 참고)
- 한국 공항이 포함되지 않은 항공편도 등록할 수 있다. 이 경우 자동 정보가 없다는 점을 안내한다.

### F-03. 내 항공편 목록
- 다가오는 항공편을 출발 순으로 보여 주고, 각 항공편에 **D-Day**를 표시한다.
- 도착이 끝난 항공편은 **'지난 항공편' 목록**으로 옮긴다. 사용자가 직접 삭제할 수 있다.

### F-04. 항공편 상세 정보
출발과 도착 정보를 모두 보여 준다.

| 구분 | 표시 항목 |
|---|---|
| 출발 | 공항, 예정·변경 시각, 터미널, 게이트, 체크인 카운터 |
| 도착 | 공항, 예정·변경 시각, 터미널, 게이트, 수하물 수취대 |
| 상태 | 정상 / 지연 / 결항 등 |
| 공항 안내 | 공항 공식 안내도 링크 |

- 게이트는 출발 직전에 정해지는 경우가 많으므로, 값이 없으면 **'미정'**으로 보여 준다.
- 체크인 카운터 정보가 없으면 항공사·공항 안내 링크로 대신한다.
- 탑승 시각은 항공 데이터에서 제공하지 않는 경우가 많다. 표시할 때는 **추정치임을 명시**한다.
- 각 정보마다 **출처**(항공 데이터 / 사용자 제보)와 **마지막 갱신 시각**을 표시한다.

### F-05. 변경 알림
아래 변경이 생기면 푸시 알림을 보낸다.

- 출발 시각 변경·지연·결항
- 터미널·게이트 배정 및 변경
- 도착 시각 변경
- 수하물 수취대 배정

알림은 **항공 데이터에서 감지한 변경**에만 보낸다. 첫 출시의 항공 데이터는 한국 공항 쪽 정보뿐이므로 **한국 공항 쪽 변경만 알림 대상**이다. 사용자 제보로 바뀐 내용은 알림 없이 화면에만 반영한다. (F-07 참고)

### F-06. 시간 임박 알림
| 기본 시점 | 내용 |
|---|---|
| 출발 24시간 전 | 내일 출발 안내 |
| 출발 3시간 전 | 공항으로 출발할 시간 안내 |
| 출발 40분 전 | 곧 탑승 시작 안내 (추정) |

- 사용자가 각 알림을 켜고 끌 수 있고 시점을 바꿀 수 있다.
- 출발 시각이 바뀌면 임박 알림 시점도 **변경된 시각 기준으로 다시 맞춘다.**

### F-07. 사용자 제보 정보 공유
항공 데이터가 부족한 항공편(소규모 항공사, 일부 지역 노선 등)을 위해 사용자가 직접 정보를 입력하고 다른 사용자와 공유한다.

| 규칙 | 내용 |
|---|---|
| 입력 가능 항목 | 출발·도착 공항과 예정 시각, 터미널, 게이트, 체크인 카운터, 수하물 수취대 |
| 입력 형식 | **형식이 정해진 값만** 받는다. 공항·터미널은 목록에서 선택하고, 게이트·카운터·수취대는 짧은 영문·숫자만 허용한다. 자유 텍스트는 받지 않는다. |
| 우선순위 | **항공 데이터 우선.** 항공 데이터에 값이 없는 항목만 사용자 제보로 채운다. |
| 공유 범위 | 같은 항공편(편명 + 날짜)을 등록한 사용자는 같은 제보 정보를 본다. |
| 수정 권한 | **그 항공편을 자기 목록에 등록한 로그인 사용자만** 수정할 수 있다. |
| 표시 | 사용자 제보 값에는 **'사용자 제보'** 표시를 붙여 항공 데이터와 구분한다. |
| 알림 | 제보·수정으로는 알림을 보내지 않는다. |
| 악용 대응 | 형식 제한과 수정 이력으로 대응한다. 신고·차단은 첫 출시에 넣지 않는다. (심사 반려 위험: [조사 결정](../02-research/README.md#알려진-위험)) |
| 공유하지 않는 정보 | 제보자 이름·이메일 등 개인 정보, 좌석·예약번호 |

### F-08. 홈 화면 위젯
- 가장 가까운 항공편의 **D-Day**와 노선을 보여 준다. (예: `D-3 · 하네다 → 인천`)

### F-09. Live Activity
- 출발 당일 잠금 화면과 다이내믹 아일랜드에 터미널·게이트·남은 시간을 표시한다. (예: `T3 · 게이트 108 · 출발까지 1:20`)
- 터미널·게이트·시각이 바뀌면 표시도 갱신한다.

### F-10. 텍스트 공유
- iOS 공유 시트로 편명·시각·터미널 등을 텍스트로 보낸다.
- 받는 사람은 앱이 없어도 된다.

### F-11. 다국어
- **한국어, 일본어, 영어**를 지원한다. 앱 화면과 알림 문구를 모두 포함한다.

### F-12. 화면 모드
- 설정에서 **시스템 / 라이트 / 다크**를 고른다. 기본은 시스템.
- 바꿀 때 화면 색이 **부드럽게 전환되는 애니메이션**을 넣는다.

### F-13. 공지사항
- 설정에 공지사항 목록을 둔다. 읽지 않은 공지는 설정 탭과 목록에 빨간 점으로 표시한다.
- **중요 공지**는 앱을 열 때 한 번 팝업으로 보여 준다.
- 공지는 한·일·영으로 작성하고, 운영자가 Firebase 콘솔에서 직접 입력한다.

### F-14. 강제 업데이트
- 서버에 저장한 **최소 버전**보다 앱 버전이 낮으면 앱을 쓸 수 없게 막고 App Store 업데이트 버튼만 보여 준다.
- 권장(닫을 수 있는) 업데이트 안내는 두지 않는다.

## 6. 지원 범위

- **플랫폼**: iOS 전용, **iOS 18 이상**
- **등록 범위**: 전 세계 항공편을 등록할 수 있다.
- **자동 정보 범위**: 첫 출시는 무료 한국 공공 데이터만 사용하므로 **한국 공항(인천, 김포 등) 쪽 정보만** 자동으로 받는다.
  - 예: 하네다 → 인천은 인천 도착 정보만 자동, 하네다 출발 정보는 사용자 제보.
  - 한국 공항이 없는 항공편은 사용자 제보로만 채운다.
  - 인천공항 실시간 정보는 출발 3일 전부터 제공된다.
- 사용자가 늘면 유료 항공 데이터를 추가해 일본 등 다른 공항으로 넓힌다. (결정 대기)

## 7. 하지 않을 것

- 항공권 검색, 가격 비교, 예약
- 예약번호(PNR)로 항공편 조회 (항공사 제휴가 필요함)
- 예약 확인 메일 자동 인식
- 체크인 대행, 좌석 선택, 마일리지 관리
- 사용자용 데모 모드

## 8. 다음 버전 후보

| 후보 | 미룬 이유 |
|---|---|
| 앱 안 공항 지도에 게이트 위치 표시 | 공항 실내 지도 데이터 확보 방법을 조사해야 한다. 첫 출시는 공식 안내도 링크로 대신한다. |
| 유료 항공 데이터로 자동 정보 범위 확대 | 월 1,000엔 목표 안에 들어오지 않는다. 사용자 증가 시 검토한다. |
| 사용자 제보 신고·차단 | 첫 출시 범위에서 제외. 심사에서 요구하면 추가한다. |
| 탑승권 바코드 스캔 등록 | 탑승권은 체크인 후에 나오므로 '예매 직후 등록'과 맞지 않는다. |
| 실시간 공유 링크 | 웹 페이지와 권한 설계가 필요하다. |

## 9. 제약 조건

- App Store **무료** 출시
- 초기 월 운영비(서버 + 항공 데이터) 목표 **1,000엔 이내**. 운영 목표이며 절대 상한을 보장하지는 않는다.
- iOS 포트폴리오용 **공개 GitHub 저장소**로 관리한다. 비밀키와 실제 여행 정보는 저장소에 넣지 않는다.

## 11. 용어

| 용어 | 뜻 |
