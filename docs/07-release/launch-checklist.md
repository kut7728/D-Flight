# 출시 체크리스트

## 1. 출시 전

### 서비스·운영
- [ ] 운영 Firebase 프로젝트 생성 (도쿄, Blaze, 예산 알림)
- [ ] 운영 Security Rules·인덱스·서버 함수 배포
- [ ] 운영 Secret Manager에 공공 API 운영 키 등록
- [ ] **인천공항 API 운영 한도 신청·승인** (서비스 주소: 지원 페이지)
- [ ] 한국공항공사 API 운영 한도 확인
- [ ] APNs 인증 키를 운영 Firebase에 업로드
- [ ] App Check 운영 강제 확인
- [ ] `config/app`의 `minimumVersion`을 첫 출시 버전으로, `appStoreUrl` 입력
- [ ] 공지사항 쓰는 법 확인 (콘솔에서 3개 언어 입력, `important`·`publishedAt`)

### 앱
- [ ] Release 빌드: 목데이터 미포함, Debug 전용 설정 없음
- [ ] [테스트 계획](../06-testing/README.md)의 전체 시나리오 재확인
- [ ] 한·일·영 문구 검수 (잘림, 큰 글자 설정)
- [ ] 다크 모드, 다이내믹 타입, VoiceOver 기본 확인
- [ ] 개인정보 매니페스트

### 공개 문서
- [ ] 개인정보 처리방침, 이용약관, 지원 페이지 GitHub Pages 공개 (한·일·영)
- [ ] 앱 전용 문의 이메일 생성
- [ ] '확인 필요' 법적 항목 확인 ([개인정보와 법적 고지](privacy.md))

### App Store Connect
- [ ] 앱 등록, 이름 중복 확인
- [ ] 부제·설명·키워드 (한·일·영)
- [ ] 스크린샷 (가상 데이터)
- [ ] 개인정보 라벨, 연령 등급 설문
- [ ] 출시 국가: 일본, 한국
- [ ] 심사 메모

### 개인 확인
- [ ] 회사의 부업·개인 활동 규정 확인 (무료 앱 공개도 대상인지)
- [ ] 저장소에 비밀 정보·실제 여행 정보가 없는지 최종 검사

## 2. 심사 대응

| 예상 반려 사유 | 대응 |
|---|---|
| 1.2 사용자 생성 콘텐츠 (신고·차단 없음) | 신고 버튼, 제보자 숨기기, 지원 연락처를 추가해 재제출. 형식 제한 입력임을 메모로 설명 |
| 2.1 기능 확인 불가 (항공편 없음) | 심사 메모에 오늘 인천 출발편 등록 방법 안내 |
| 4.8 로그인 | Sign in with Apple 제공 확인 |
| 5.1.1(v) 계정 삭제 | 앱 안 삭제 경로 안내 |
| 5.1.1 개인정보 | 처리방침 URL, 라벨 일치 확인 |

반려되면 사유를 이 표에 기록하고 결정 문서를 고친다.

## 3. 출시 후 운영

| 항목 | 주기 | 방법 |
|---|---|---|
| 월 비용 | 매주 | Google Cloud 결제 화면, 예산 알림 메일 |
| 공공 API 사용량 | 매주 | `system/quota_*` 기록, 80% 초과 빈도 |
| 서버 오류 | 매주 | Cloud Logging 오류 로그 |
| 앱 충돌 | 매주 | Xcode Organizer 충돌 보고 (별도 SDK 없음) |
| 문의 메일 | 수시 | 앱 전용 이메일 |
| 장난 제보 | 문의 시 | `reportHistory`로 확인, 서버에서 값 되돌림 |

**유료 데이터 추가 검토 조건** (조사 결정 D-04)
- 한국 공항이 없는 항공편 등록 비율이 높거나, 일본 공항 정보 요청이 많을 때
- 비용 목표를 함께 다시 정한다.
